# Action Branch — 공문/업무요청 → `10_Areas/{area}/` 업무사안 노트

> 파일명이 `mode-*` 규약을 따르지 않는 이유: action/reference는 사용자가 고르는 실행 모드가 아니라
> 스킬이 문서를 판별한 분류 결과다 (`docs/runbook.md` § Harness Asset Placement & Naming).

`01_Inbox/action/`의 파일·폴더를 `99_Template/_업무사안.md` 구조의 업무사안 노트로 변환한다. 노트 작성 전 항상 템플릿을 Read로 확인한다.

**워커 규약**: 이 문서는 `inbox-action-worker`가 읽는다. 워커는 사용자와 대화할 수 없고 다른 에이전트를 호출할 수 없다. "확인 필요"는 전부 노트 `## 열린 질문`(또는 보고)으로 반환하고, 원본 삭제·vault-navigator·tag-validator는 오케스트레이터 몫이다.

처리 대상 목록과 `10_Areas/` area 목록은 오케스트레이터가 입력으로 준다 — 재스캔하지 않는다(목록이 없는 직접 실행 경로에서만 `ls 10_Areas/`).

## 처리 단위

- **인라인 텍스트 입력**(경로 없이 내용을 받은 경우): §1 문서 읽기, §5의 첨부 복사, §6 삭제 권고를 건너뛴다.
- `01_Inbox/action/` 바로 아래 **하위 폴더** = 업무 단위 하나(안의 파일은 첨부). **단독 파일** = 업무 단위 하나. 혼재해도 각각 독립 처리. 빈 폴더는 건너뛴다.

## 1. 문서 읽기

| 확장자 | 처리 |
|--------|------|
| `.txt` | Read |
| `.pdf` | `references/pdf-reading.md` 절차 (분류 → PyMuPDF → 필요 시 OCR) |
| `.xlsx`, `.docx`, `.hwp` 등 | 내용 분석 없이 첨부로만 |

## 2. 문서 내용 분석

- **업무 제목**: 공문 제목 또는 핵심 요청 (간결하게)
- **요약**: 요청 내용·배경·주요 사항 3~5줄
- **발신 부서/담당자** (있으면)
- **공문 번호**: `부서명-숫자(YYYY. M. D.)` — 기안일자를 반드시 함께 적는다(예: `총무과-7453(2026. 3. 12.)`). 부서가 매년 번호를 초기화하므로 날짜 없이는 다른 해 문서와 구분되지 않는다. 문서에 날짜가 없으면 번호만, 번호도 없으면 항목 생략.
- **할 일**: 요청받은 조치 (있으면)
- **기한** (있으면)
- **문서 성격**:
  - 에러 로그·스택 트레이스·ERR_INFO 포함 → `## 열린 질문`에 "에러 로그 포함 — incident-analyst 추가 호출 필요?"
  - 코드 수정·쿼리 변경·before→after 포함 → `## 열린 질문`에 "개선 사항 포함 — improvement-planner 추가 호출 필요?"
  - 일반 업무 요청 → 업무사안 노트만

## 3. Area 판단

1. 오케스트레이터가 준 area를 쓴다.
2. (직접 실행 경로) 아래 키워드로 후보를 고르고 실제 `10_Areas/` 폴더에 있는지 확인한다.
3. 없거나 판단 불가면 `기타/`로 생성하고 `## 열린 질문`에 "area 확정 필요: 후보 {목록}".

| 키워드 | Area | 태그 |
|--------|------|------|
| 수업, 성적, 강의평가, 강의계획, 보강, 출석 | `수업성적/` | `#업무/수업성적` |
| 수강신청, 수강, 수강정정, 장바구니 | `수강신청/` | `#업무/수강신청` |
| 교직, 교원자격, 수료증, 적인성검사 | `교직/` | `#업무/교직` |
| 졸업, 학위, 학위수여 | `졸업/` | `#업무/졸업` |
| 교원, 공채, 임용, 채용 | `전임교원공채/` | `#업무/전임교원공채` |
| 예산, 계약, 구매 | `예산관리/` | `#업무/예산관리` |
| 전자문서, 결재, 문서관리 | `구전자문서/` | `#업무/구전자문서` |
| 개발, 시스템, 서버, 보안, 네트워크, 권한, 메뉴관리, SSO | `개발공통/` | `#업무/개발공통` |

태그는 `#업무/{10_Areas 폴더명}` 단일 접두어. `학사/`·`공통/` 같은 중간 접두어는 `validate-tags.sh`가 거부한다.

## 4. 유사 노트 힌트 · MOC 확인

**4-A. 힌트 (오케스트레이터 제공)** — 유사 노트 경로(최대 5건)와 태그 패턴. 활용: 태그를 `## 관련`의 **후보 태그**로, 직접 관련 노트는 `[[노트명]]`으로, 조치 사항은 할 일 제안에 참고. 힌트가 비면 건너뛴다.

**4-B. MOC** — `ls "_Wiki/topics/{도메인}-운영-MOC.md"` (또는 `qmd search "{도메인}-운영-MOC" -n 3`). 있으면 `## 관련`에 `[[_Wiki/topics/{도메인}-운영-MOC]]` 추가, 없으면 생략.

## 5. 노트 생성 및 파일 복사

첨부 유무로 레이아웃이 갈린다 (`docs/conventions.md` → `10_Areas/ Depth Rules`):

```
# 첨부 있음
10_Areas/{area}/{YYYYMM}_{요약}/
├── _{YYYYMM}_{요약}.md     ← 노트 (_ 접두)
└── 공문.pdf, 기타.xlsx      ← 원본 첨부

# 첨부 없음 (인라인 텍스트, 또는 복사할 원본이 없는 단위)
10_Areas/{area}/{YYYYMM}_{요약}.md   ← 단일 파일, _ 접두 없음, 래퍼 폴더 없음
```

순서:

1. `10_Areas/{area}/`가 없으면 생성하고 `## 열린 질문`에 "신규 area '{area}' 생성함 — 확인 필요".
2. 경로 산출 — `new_work_path.py` (아래). 첨부가 없으면 `--flat`.
3. 첨부 복사 (첨부 있을 때만). 실패한 파일은 건너뛰고 보고.
4. `99_Template/_업무사안.md` Read.
5. `note` 경로에 노트 작성.

### 경로 산출 — `new_work_path.py`

슬러그·sanitize·`_2/_3` 증분·공문번호 중복 감지는 스크립트가 한다(동작·옵션은 `--help`). LLM이 직접 슬러그 로직을 쓰지 않는다.

```bash
python3 .claude/skills/inbox-process/scripts/new_work_path.py \
  수업성적 "강의평가 결과 조회 관련" --yyyymm 202604 \
  --doc-number "학사관리과-1234" --json [--flat]
```

- `--doc-number`에는 **날짜 없는 `부서명-숫자`만** 넘긴다 (substring 매칭이라 날짜가 붙으면 중복을 놓친다). 노트 본문에는 날짜 포함 형식으로 적는다.
- 반환 JSON: `folder`(`--flat`이면 `null`), `note`, `slug`, `sanitized_title`, `duplicate_candidates`.
- **`duplicate_candidates`가 비어 있지 않으면 노트를 만들지 않는다.** 열린 질문으로 반환:

  ```
  ⚠️ 중복 공문 의심: {공문 번호}가 기존 노트에서 발견됨.
  기존 노트: {duplicate_candidates}
  → 사용자 확인 필요: 기존 노트에 추가할지, 새 노트를 만들지?
  ```

  연도가 다른 동일 번호도 후보로 걸리므로 노트의 날짜 병기가 판별 근거가 된다.

### 노트 작성 기준

| 섹션 | 내용 |
|------|------|
| frontmatter | `type: work`, `status: open`. 공문이면 `doc_date: YYYY-MM-DD`(시행일), 접수일이 다를 때만 `recv_date`. `date created/modified`·`tags`·`systems`·`people`·`area`는 넣지 않는다 |
| `#` 제목 | `{업무 제목}` — 날짜 프리픽스 없음 (날짜는 `doc_date`) |
| `## 관련` | 후보 `#업무/`·`#부서/{부서명}/{직급}_{이름}` 태그, 유사 노트 `[[노트명]]`, MOC 링크(4-B에서 확인된 경우만) |
| `## 현황` | 요약 3~5줄 |
| `## 관련 문서` | 첨부 있을 때만 `[[첨부파일.pdf]]` (embed `!` 금지). 첨부 없으면 헤딩+콜아웃 전체 생략 — 빈 `[[ ]]` 금지 |
| `## 할 일` | `- [ ] 내용 📅 YYYY-MM-DD ➕ YYYY-MM-DD`. 기한이 없으면 `📅`는 오늘 |
| `## 처리 결과` | `- ` |

한국어로 쓰고 기술 용어는 영어 유지.

## 6. 삭제 권고 (워커는 삭제하지 않음)

성공한 원본 경로를 `## 삭제 권고 (action)`으로 보고한다. 제외: 노트 생성 실패 건, 열린 질문이 남은 건(중복 의심 포함), 인라인 텍스트.

```
## 처리 완료 (action)
- 📄 강의평가 결과 조회 관련 → 10_Areas/수업성적/202604_강의평가 결과 조회 관련/

## 삭제 권고 (action)
- /.../01_Inbox/action/강의평가 결과 조회 관련.pdf
```

`/tmp/extracted_*.pdf`는 워커가 정리해도 되고 오케스트레이터가 일괄 정리한다.

## 에러 처리 (모두 열린 질문·보고로 반환)

- **PDF 읽기 실패**: `pdf-reading.md` 순서대로 시도 후 실패하면 건너뛰고 보고.
- **동일 폴더명 존재**: 스크립트가 `_2/_3`을 붙인다. `## 열린 질문`에 "기존 노트와 병합 검토 필요: {기존 경로}".
- **첨부 복사 실패**: 해당 파일만 건너뛰고 노트 생성은 계속.
- **유사 노트 힌트 없음**: 4-A 건너뜀.
