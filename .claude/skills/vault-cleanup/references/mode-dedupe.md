# Mode: Dedupe — 시맨틱 중복 탐지

`qmd vsearch`로 볼트 내 의미상 중복 노트 짝을 탐지하고 검토 리스트를 제시한다.
**자동 삭제·통합 금지 — 목록 제시 후 사용자 결정.**

## Step 1: 탐지 범위 확정

사용자 요청에서 탐지 대상을 확인한다. 명시 없으면 기본 범위:

- `14_Changes/incident/` + `14_Changes/improvement/` (가장 중복이 많은 영역)
- `10_Areas/` 는 사용자 요청 시에만 추가
- `90_Archive/` 는 기본 제외 (--include-archive 명시 시만)

## Step 2: 중복 후보 샘플링

전체 노트 순회는 qmd 호출 비용이 크므로, 다음 우선순위로 후보를 추린다:

1. **파일명 유사성**: `ls 14_Changes/ | sort`로 같은 날짜·유사 제목 짝을 시각 확인
2. **동일 프로시저 + 동일 날짜**: incident 폴더 내 Grep으로 확인
3. **사용자 지정 키워드**: 특정 업무 도메인만 검사하는 경우

후보 1개당 실행:

```bash
qmd vsearch "{노트 제목 또는 ## 프로시저 섹션 내용}" -n 5 --json
```

## Step 3: 중복 후보 목록 제시

유사도 기준 분류:

| 유사도 | 분류 | 의미 |
|--------|------|------|
| 0.90 + | MERGE 검토 | 두 노트 Read 후 통합 결정 권고 |
| 0.85–0.89 | REVIEW | 의미 구분 확인 후 유지/통합 결정 |
| 0.85 미만 | 제외 | 보고하지 않음 |

보고 형식:

```
## 시맨틱 중복 후보

| # | 노트 A | 노트 B | 유사도 | 권고 |
|---|--------|--------|--------|------|
| 1 | [[14_Changes/incident/.../노트A]] | [[14_Changes/incident/.../노트B]] | 0.92 | MERGE 검토 |
```

후보가 없으면 "중복 후보 없음"으로 보고하고 종료.

## Step 4: Wiki Deadlink 점검 (archive 이동 후 선택 실행)

`mode-archive.md` 실행으로 노트가 90_Archive로 이동된 직후, 선택적으로 실행한다.

이동된 노트 파일명이 `_Wiki/`에서 wikilink로 참조되고 있는지 확인:

```bash
grep -rn "{이동된 노트 파일명}" \
  "_Wiki/index.md" "_Wiki/log.md" "_Wiki/topics/" 2>/dev/null
```

발견된 deadlink 목록을 보고한다. 자동 수정은 하지 않으며, 수정 여부를 사용자에게 확인한다. 승인 시 **직접 Edit**으로 고친다 (링크 한두 줄 수정에 에이전트 왕복 금지 — AGENTS.md 위임 비용 규칙 #3).
