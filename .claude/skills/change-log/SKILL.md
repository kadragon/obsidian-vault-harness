# 주간 기능 개선 내역 보고서 생성

직전 주(월~일)에 처리된 통합학사시스템 업무를 볼트에서 수집하여 아래 형식으로 정리한다.

## 출력 형식 (예시)

```
[2026-03-16~2026-03-22]

1. [학사 > 수업성적]
- (성적관리) 학점교류(아웃바운드)관리에서 교환학생 성적 입력 오류 및 대학검색 오류 수정
- (수강관리) 개인연구 과목 신청 시 지도교수 선정 여부 확인

2. [학사 > 졸업]
- (졸업사정관리) 졸업사정처리시 업무일정 예외자 미적용 오류 수정

※ 건의사항 및 문의: kadragon@knue.ac.kr
```

코드 블록 없이 바로 출력한다.

---

## 카테고리 매핑

`[카테고리 > 도메인]` 형식으로 묶는다. 카테고리는 스크립트가 부여한 `category` 필드를 그대로 사용한다 — 도메인→카테고리 매핑의 단일 출처는 `scripts/collect_weekly_notes.py`의 `CATEGORY_MAP`이다. 여기에 표를 두지 않는다 (표를 만들면 스크립트와 드리프트한다).

---

## 워크플로우

### Step 1 — 대상 노트 수집 (스크립트 실행)

Bash tool로 실행한다 (Windows 환경이어도 Bash tool 사용):

```bash
python3 .claude/skills/change-log/scripts/collect_weekly_notes.py --vault .
```

특정 주를 지정할 때는 `--week YYYY-MM-DD`(해당 주 내 임의 날짜)를 추가한다.

스크립트 출력 JSON:
- `week_start` / `week_end` : 보고 기간 (항상 월~일)
- `notes[]` : 각 노트의 `path`, `area`, `category`, `source`, `title`, `tag`

노트가 0개이면 "직전 주(YYYY-MM-DD ~ YYYY-MM-DD)에 해당하는 노트가 없습니다."라고 안내하고 종료한다.

### Step 2 — 각 노트 읽기 및 정보 추출

수집된 모든 노트를 Read로 읽고, **아래 제외 기준을 먼저 적용**한 뒤 통과된 노트만 보고서에 포함한다.

#### 수집 제외 기준

다음 중 하나라도 해당하면 보고서에서 제외한다:

| 제외 유형 | 판단 기준 |
|----------|----------|
| **단순 1회성 처리** | DB 직접 조작(DELETE/INSERT/UPDATE), 개인 데이터 삭제·수정 요청 처리 등 시스템 변경 없이 데이터만 조작한 경우 |
| **미완료 개발** | 개발·수정이 이번 주 안에 완료되지 않은 경우 (설계·협의·요건검토 완료만으로는 포함하지 않음 — 실제 코드·SP·화면 변경이 merge/배포까지 완료되어야 함) |

위 기준 통과 후 아래 세 가지를 추출한다:

#### ① 서브메뉴 (괄호 표기)

우선순위대로 확인:

1. `#업무/{area}/{subarea}` 태그의 **subarea** 부분  
   예: `#업무/수업성적/성적관리` → `(성적관리)`
2. `## 📑 메뉴` 섹션의 마지막 2~3번째 경로 요소  
   예: `통합학사 > 수업성적 > 성적관리 > 성적입력` → `(성적관리)`
3. 위 모두 없으면 노트 제목·내용에서 도메인 맥락을 고려해 추론  
   예: `졸업사정처리` 포함 → `(졸업사정관리)`, `학점교류(아웃바운드)` → `(성적관리)`

같은 도메인 내 서브메뉴가 같은 항목은 한 서브메뉴 아래 연속으로 배치한다.

#### ② 설명 (1줄)

노트 제목을 보고 형식에 맞게 간결하게 다듬는다:

| 유형 | 표현 방식 |
|------|----------|
| 오류·장애 수정 | `~ 오류 수정` |
| 신규 기능·메뉴 | `~ 기능 추가` / `~ 메뉴 개선` |
| 쿼리·성능 최적화 | `~ 성능 개선` |
| 정책·조건 변경 | `~ 조건 추가` / `~ 정책 변경` |

**기술 용어 제거 규칙**: 독자는 시스템 담당자가 아닌 일반 보고 수신자임을 전제한다. DB 오류코드(ORA-xxxxx), 내부 파일명(`.jrf`, `.xml`), SQL 힌트/플랜 용어(JPPD, CBO, NL 조인), 컬럼·테이블명은 설명에 포함하지 않는다. 무엇이 개선되었는지 기능 관점으로만 서술한다.

- ❌ `교과목 신설 반려 사유 컬럼 크기 초과(ORA-12899) 오류 수정`
- ✅ `교과목 신설 반려 사유 저장 오류 수정`
- ❌ `성적입력현황 조회 JPPD 병목 Oracle 힌트로 성능 개선`
- ✅ `성적입력현황 조회 성능 개선`

괄호 안 고유명사(학번, 이름)는 생략하고 핵심만 남긴다.

### Step 3 — 그룹화 및 출력

1. `[카테고리 > 도메인]` 기준으로 항목을 묶는다
2. 도메인 정렬 순서: 학사(수업성적→수강신청→졸업→교직→등록) → 행정 → 부속(전임교원공채) → 공통 → 기타
3. 헤더(`[YYYY-MM-DD~YYYY-MM-DD]`)는 스크립트의 `week_start` / `week_end` 사용
4. 마지막 줄에 `※ 건의사항 및 문의: kadragon@knue.ac.kr` 추가

### Step 4 — 클립보드 복사

1. **파일 저장** — Bash heredoc으로 저장한다 (`.claude/change-log-report.txt`는 재실행마다 존재하므로 Write tool은 read-first 오류 발생 — Bash redirect 사용):

```bash
cat > ".claude/change-log-report.txt" << 'REPORT'
[보고서 전문 붙여넣기]
REPORT
```

2. **클립보드 복사** — OS에 맞는 클립보드 도구로 복사한다 (mac=`pbcopy`, Windows/git-bash=`clip`):

```bash
f=.claude/change-log-report.txt
if command -v pbcopy >/dev/null 2>&1; then pbcopy < "$f"
elif command -v clip >/dev/null 2>&1; then clip < "$f"
else echo "클립보드 도구 없음 — 파일 직접 복사: $f"; fi
```

완료 후 "클립보드에 복사되었습니다. 바로 붙여넣기 하세요."라고 안내한다 (클립보드 도구가 없으면 파일 경로를 안내).

### Step 5 — 불확실한 항목 처리

카테고리나 서브메뉴 추론이 불명확한 경우:
- 서브메뉴는 `(확인 필요❓)` 표기 후 추후 수정 요청
- 도메인이 CATEGORY_MAP에 없는 경우 `[기타 > {태그값}]`으로 표기하고 사용자에게 안내

수정 요청이 있으면 보고서를 다시 생성하고 Step 4를 반복한다.
