# 과업심의 요청 사전검토 (간사 — 위원 발송 전)

**어느 단계인가.** `10_Areas/과업심의/과업심의_프로세스.md` 기준 **Step 4(첨부 목록 검증) 이후 ~ Step 7(외부위원 발송) 이전**.
접수된 심의자료를 위원 관점의 렌즈로 훑되, **산출물은 위원용이 아니라 발주부서(대상자)용**이다.
목적은 **위원에게 나가기 전에 자료를 고치게 하는 것** — 심의 결과를 내는 것이 아니다.

**최종 산출물은 발주부서 전달용 PDF다.** 볼트 노트는 그 판단 근거를 남기는 기록이다.

```
심의자료 접수 → [이 스킬] 사전검토 → 보완요청 PDF 발송 → 회신·보완 → 위원 발송(Step 7) → 심의
                                   └ 미회신이면 원본 그대로 상정 + 검토결과 참고 첨부
```

**판정 등급은 위원회 몫이다.** 사전검토 단계에서 `원안 확정`·`재심의` 등을 확정하지 않는다.
등급은 노트에만 상정 참고용으로 남기고, **전달본에는 A(발송 전)/B(심의 시)로 시급성만** 싣는다.

**핵심 원칙 6가지**

0. **모든 지적은 4요소로 닫는다** — `{근거}에 따라 {당위}하여야 하나, {대상 문서·위치}에 {실제}로 되어 있음. 요청 — {조치} 바람`.
   조문·기준은 `references/legal-basis.md`에서 가져온다. 근거를 못 대는 항목(L4)은 지적이 아니므로
   **노트에만 남기고 전달본에서는 뺀다** (`output-format.md` §0-1·§2-2).
   발행 전 `scripts/lint_findings.py`로 기계 검사한다.
1. **절차가 내용에 앞선다.** 위원 구성·간소화 대상·제척부터 본다(체크리스트 축 0). 여기서 걸리면 내용 판정 자체가 무의미하다.
2. **금액과 기간은 역산한다.** 산출내역서를 읽고 끝내지 말고 `scripts/cost_check.py`로 되짚는다. 산출근거가 시장 견적뿐이면 그 자체가 최상위 지적사항이다.
3. **재발을 먼저 찾는다.** `references/recurring-defects.md`의 기지(旣知) 지적이 다시 들어와 있는지가 가장 방어하기 쉬운 지적이다.
4. **문서 간 대조가 본체다.** 심의요청서 · 제안요청서 · 산출내역서 · 기본계획 · 자문결과가 서로 어긋나는 지점이 실제 결함이 있는 곳이다.
5. **발주부서가 단독 확정할 수 없는 사항은 판정하지 말고 보류로 분류한다.** (계약·회계부서 소관, 소관부처 유권해석 필요 등)

## Step 0: 대상 파악

사용자가 폴더 경로를 준 경우 그대로 쓴다. 없으면 `01_Inbox/action/` 또는
`10_Areas/과업심의/{회차폴더}/{확정요청번호}/심의자료/`에서 찾는다.

사업 유형을 먼저 판정한다 — **이후 체크리스트 범위가 갈린다.**

| 유형 | 판정 근거 | 검토 범위 |
|------|----------|----------|
| SW **개발**사업 | 기능점수(FP) 산정표·적정 사업기간 산정표 존재, 신규 개발 과업 포함 | 전체 (대가산정 + 적정기간 + 평가기준 + 법제도) |
| 물품구매·구독·임차·유지보수 | 규격서·견적서 중심, 개발 산출물 없음 | 대가산정·적정기간 제외, 정합성 + 규격 경쟁성 + 계약조건 |

이어서 **심의 유형**을 판정한다 — 절차 요건이 갈린다(`references/legal-basis.md` §5).

```
총 사업금액 ≤ 1억원  또는  상용SW·표준화 보급 시스템 구매  또는  기심의 사업의 변경없는 추가
  ├─ 예   → 간소화 심의 (위원 2인 이상, 외부위원 과반수 이상)
  └─ 아니오 → 정식 심의 (위원장 포함 5~10명, 외부위원 과반수)
```

간소화 근거는 **대학 운영지침 제5조제3항의 해당 호를 정확히 특정**해 적는다 — 조건마다 호가 다르다.

| 조건 | 대학 운영지침 §5③ | 상위 지침 §25③ |
|------|-----------------|---------------|
| 총 사업금액 1억원 이하 | **제1호** | 제1호 |
| 상용SW·표준화 보급 정보시스템 구매 | **제2호** | 제2·3호 |
| 기심의 사업의 변경 없는 추가 | **제3호** | 제4호 |
| 정보시스템 감리 사업 | **없음** | 제5호 |
| 전자정부사업관리 위탁(PMO) | **없음** | 제6호 |

**대학 지침에는 감리·PMO 위탁 2개 유형이 없다.** 상위 지침상 간소화 대상이어도
대학 지침에 근거가 없으므로 **정식 심의**로 본다.

정식 심의 대상인데 2인 체제로 운영 중이면 **내용 검토 전에 사용자에게 알린다.**


**스캔본 PDF는 여기서 잡힌다.** `INDEX.md`에 `SCANNED`로 표시되면

시장조사 결과·견적서가 스캔본인 경우가 많고, **그 안에 가장 결정적인 근거가 들어 있다** — 건너뛰지 않는다.

## Step 5: 지적 정리 및 산출물

`references/output-format.md`를 Read하여 형식을 맞춘다. **§0(지적 문장 규격)이 먼저다.**

### 5-1. 지적을 4요소로 확정

각 지적을 `{근거} → {당위} → {실제·원문 인용과 위치} → {요청}` 문장으로 쓴다.
근거 등급(L1 조문 / L2 가이드·기준 / L3 문서 간 불일치 / L4 관행)을 매기고,
**L4는 지적에서 빼 노트에만 남긴다 — 전달본에 권고 절은 없다.**

**전달본에 실을지는 별도 판단이다.** 검토하며 찾은 것을 전부 싣지 않는다. 각 항목을 두 질문으로
거른다: (1) 이 항목을 안 고치면 위원이 오독하거나 심의가 되돌아오는가? (2) 수신자가 근거를 보고
"무엇을 어떤 형태로 낼지" 바로 알 수 있는가? 둘 중 하나라도 아니면 노트행이다.
근거가 약한 항목을 끼워 넣으면 강한 지적까지 같이 값이 깎인다 — 실제로 매 회차 수신 전에
사용자가 하위 항목을 손으로 쳐냈다. 채택 기준과 묶는 방법은 `output-format.md` §2-2.

**금액 전제를 먼저 확정한다.** 추정가격 2천만원 미만이면 소액수의계약 대상이라
경쟁입찰·제안요청서·규격 공개를 전제한 지적은 걸지 않는다(과업지시서가 정상 서식).

시급성 2단계로 분류한다 — **판정 등급이 아니다.**

| 구분 | 기준 | 기한 |
|------|------|------|
| **A** | 과업범위·사업금액·사업기간 판단에 직접 영향. 근거 자료 추가 제출 필요 | **위원 발송일 − 2영업일** |
| **B** | 표기·정합성. 위원 검토 진행에는 지장 없음 | 심의 개최일 전까지 |

### 5-2. 산출물 2종

| # | 산출물 | 용도 | 문체 |
|---|--------|------|------|
| 1 | **볼트 노트** `10_Areas/과업심의/{회차폴더}/{확정요청번호}/심의의견_{확정요청번호}.md` (회차 통합이면 `{연월}_제{N}차과업심의_심의의견.md`) | 판단 근거 기록 + 상정용 판정(안) — 등급 기준은 `output-format.md` §1-1 | 평서형 `~다` 허용 |
| 2 | **발주부서 전달용 PDF** — 기본형 **보완요청본**, 지적이 표기 오류뿐이면 검토의견본 | 대상자가 고치게 하는 문서 | 개조식 `~함 / ~바람` |

**전달본에는 수신자가 할 일만 싣는다** — 판정(안) 등급·제척·위원 지명·상정 일정·심의결과서 기재는 노트에만.
반대로 전달본에만 있는 것은 발신 메타 4종과 "확인 완료" 절이다 → `output-format.md` §2.
미보완·미회신 시의 불이익 고지 문장은 전달본에 싣지 않는다 → `output-format.md` §2-3.

## Step 6: 보완본 재검토 (회신이 온 경우)

전량 재검토하지 않는다. **델타만** 본다.

1. 회신 문서와 **직전 전달본의 A·B 항목을 1:1 대조** — 각 항목이 해소/미해소/부분해소 중 무엇인지 표로 적는다.
2. **보완 과정에서 다른 문서가 어긋났는지 확인** — 금액을 고치면 산출내역서·심의요청서·사업계획서 3자가 다시 갈라진다.
   `cost_check.py sum`을 재실행한다.
3. **미해소 항목만** 2차 요청으로 남기고, 나머지는 "해소 확인"으로 닫는다.
4. 노트에 회신 문서번호·일자와 해소 현황 표를 append 한다(기존 지적은 지우지 않는다 — 이력이 재발 탐지 근거다).
5. 미해소 항목이 남은 채 위원 발송일이 되면 **원본 그대로 상정 + 검토결과 참고 첨부**로 진행하고 사용자에게 알린다.

## 하드 스톱 — 사용자에게 확인

- **정식 심의 대상(1억원 초과 등)인데 위원 구성이 요건 미달**(5명 미만 또는 외부위원 과반수 미달) → 내용 검토 전에 알린다.
- 심의요청 결재권자와 심의위원장이 동일인인 경우 → 제척·회피 사안(대학 운영지침 §7①2호). 판정 전에 알린다.
- **조문을 인용하기 전에 현행본을 확인**한다. 지침 고시번호·시행일은 `legal-basis.md` 상단 버전 주의 참조 — 확인한 번호를 심의의견에 함께 적는다.
- 승인 체크(위원별/종합 심의결과서 기입)는 이 스킬 범위 밖 — `과업심의_프로세스.md` Step 10.
  실제 승인 확인 없이 체크하지 않는다.
- 지적사항에 특정 업체명을 노출할지 여부 → 대외 전달본이면 확인 후 익명화(`RFI 회신 업체` 등).
- **위원 자료 발송 예정일을 모르면 회신 기한을 지어내지 않는다** — 사용자에게 확인한다(회신 기한의 근거가 곧 발송일이다).
- **전달본 발송 자체는 사용자 결재 사항이다.** 이 스킬은 PDF까지 만들고 멈춘다 — 공문 기안·발송은 `gongmun-draft`.
