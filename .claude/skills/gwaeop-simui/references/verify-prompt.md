# 지적별 반박 검증 — Step 5-2

작성자(메인 스레드)가 자기 지적을 다시 읽으면 처음과 같은 전제를 되풀이한다. 그래서 A 항목마다 검증자를 따로 둔다.
검증자의 임무는 지적을 **반박하는 것**이다. 확인 도장을 찍는 역할이 아니다.

## 1. 실행

- 전달본 A 항목 1건마다 `Agent`(subagent_type `general-purpose`, `run_in_background: true`)를 하나씩 띄운다. **한 메시지에 모두 담아 병렬로** 호출한다.
- B 표 가운데 L1 조문을 인용한 행이 있으면 에이전트 1개에 묶어 검증할 수 있다(선택).
- 비용은 에이전트 1개당 약 80~120k 토큰이다. 근거는 `docs/harness-log.md`.
- 결과가 모두 모인 뒤 반영한다. 도착하는 대로 부분 반영하면 A 번호가 여러 번 흔들린다.

## 2. 프롬프트 템플릿

`{{…}}`를 채운다. 공통 맥락은 모든 에이전트에 같게 넣는다.

```text
You are an adversarial verifier for a Korean public-procurement pre-review finding. Do not trust the finding; try to refute it. Respond in Korean. You cannot ask the user anything — state assumptions and finish. Do not spawn further agents.

## Context
- 사업: {{사업명}}, 발주·계약 주체 표기 "{{RFP 표지·안내문 원문 그대로}}", 사업금액 {{금액}}원(VAT {{포함/별도}}), 추정가격 {{금액}}원, {{계약방법}}, 사업 유형 {{SW 개발 / 콘텐츠 / 구매 등 — 판단 근거 한 줄}}.
- 원문 추출본: {{extract 폴더의 .txt 절대경로 목록 — 지적과 관련된 파일·행 범위 표시}}. 이미지 원문은 {{png 경로}} (Read로 본다).
- 법령 조회: ToolSearch로 `mcp__korean-law__search_law`, `mcp__korean-law__get_law_text`, `mcp__korean-law__execute_tool`을 로드한다. 행정규칙 전문은 execute_tool tool_name "get_admin_rule", params {"id": "<행정규칙일련번호>"}로 받는다. {{이미 확보한 MST·id가 있으면 적는다}}. WebSearch·WebFetch도 쓸 수 있다.

## Finding to verify ({{번호}})
{{노트의 지적 문장 원문 — 근거·당위·실제·요청 전부}}

## Check
1. 인용문이 원문과 글자 그대로 일치하는가. 위치(절·요구사항 ID·행)가 맞는가. 같은 사항을 RFP의 다른 곳(붙임·특약·서식)이 이미 규정하고 있지 않은가.
2. 인용 조문이 주장한 내용을 실제로 말하는가 — 현행 원문을 조회해 확인한다. 강행 규정("하여야")인가, 임의 규정("할 수 있다")인가.
3. 적용 대상인가 — 계약 주체(국가기관 / 국립 교육기관 / 산학협력단 등 별도 법인), 금액 구간(고시금액·1억원·20억원), 사업 유형. 조문의 정의 규정까지 거슬러 확인한다.
4. 예외 조항이나 단서에 해당해 지적이 무너지지 않는가.
5. 공정성 — 과장("부재", "이행 불가")이나 더 강한 근거가 있는가. 빠뜨린 모순이 있는가.
{{지적별 추가 확인 사항}}

## Output (≤350 words)
- 판정: CONFIRMED / PARTIAL / REJECTED (하위 주장이 여럿이면 각각)
- 근거별 확인 결과 (조문 원문 인용은 짧게, 행 번호 포함)
- 권장 수정 문구
- 확인하지 못한 가정
```

## 3. 반영

| 판정 | 처리 |
|------|------|
| CONFIRMED | 유지한다. 검증자가 제시한 보강 근거와 추가 모순만 반영한다 |
| PARTIAL | 검증자가 지목한 과장이나 약한 근거를 고쳐 쓴다. 근거 조문을 바꾸면 새 조문을 메인 스레드가 직접 원문으로 확인한다 |
| REJECTED | 전달본 A에서 뺀다. 문서 간 불일치처럼 남는 근거가 있으면 B나 노트로 강등한다 |

- 검증자가 출처 없이 단정한 수치나 조문(예: 고시금액 액수)은 옮기지 않는다. 원문을 확인하기 전까지는 노트 `판단 보류`에 둔다.
- 검증자끼리 결론이 엇갈리거나, 검증자 판정이 사용자가 알려준 사실과 충돌하면 사용자 사실이 우선한다. 충돌한 내용은 보고에 적는다.
- 반영한 뒤 `lint_findings.py`를 다시 돌린다. 검증자의 권장 문구가 4요소 정규식을 통과하지 못하는 일이 흔하다.
