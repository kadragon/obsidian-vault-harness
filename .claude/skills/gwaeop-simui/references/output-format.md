# 산출물 형식

## 1. 볼트 노트 — `{...}_심의의견.md`

위치: `10_Areas/과업심의/{회차폴더}/{연월}_제{N}차과업심의_심의의견.md`
단일 사업 검토면 사업 폴더 안에 `심의의견_{확정요청번호}.md`.

선례: `10_Areas/과업심의/202607_제7차과업심의/202607_제7차과업심의_심의의견.md`

```markdown
---
type: work
status: open
---

# 제{N}차 과업내용 확정 심의 — 위원 검토의견

## 관련

- #업무/예산관리
- [[{회차}_사업목록]]

## 현황

**심의일:** YYYY년 M월 D일 (서면심의) · **대상:** N개 사업 합계 N원
**검토 자료:** 각 사업 `심의자료/` 하위 심의요청서·제안요청서·산출내역서·견적서 전량

### 종합 판정

| 확정요청번호 | 사업명 | 금액 | 판정(안) | 핵심 보완사항 |
| --- | --- | ---: | --- | --- |

### 최우선 — {제척·공정성 등 최상위 사안이 있을 때만}

---

### {확정요청번호} {사업명} — {판정}

**근거 검증**

| 검증 항목 | 결과 |
| --- | --- |

**지적사항**

1. **{한 줄 제목}** — {원문 인용 또는 수치 대조} → {요구 조치}
...

## 비고

- 사업 유형(개발/구매)과 그에 따른 검토 범위 한정
- 판단 불가 항목과 그 사유 (예: 견적서 부재로 시장가 적정성 판단 불가)
```

**작성 규칙**

- 지적 1건 = **한 줄 제목(굵게) + 근거 + 요구 조치**. 배경 설명으로 늘리지 않는다.
- 수치는 반드시 대조 형태로: `사업계획서 21,900,000원 vs 산출내역서 21,700,000원`
- "판단 불가"는 판단 불가로 적는다. 근거가 없는데 적정으로 넘기지 않는다.
- 재발 항목은 `references/recurring-defects.md`의 번호(A-4 등)를 병기한다.

## 2. 발주부서 전달용 PDF

요청이 있을 때만 만든다. 노트가 1차 산출물이다.
**용도에 따라 골격이 갈린다** — 아래 2-1과 2-2를 혼동하지 않는다.

### 2-1. 검토의견본 — 심의 결과·판단을 전달

```
과업심의 검토의견
{사업명}
──────────────────────
1. 검토 개요      (검토 대상 / 사업 개요 / 검토 자료 / 대조 기준)
2. 검토 결론      (판정 + 처리의견 표)
가. 의결 전 해소 필요
나. 문서 정합성·법제도 표기   ← 표 형식이 읽기 쉬움
다. 과업 실현가능성
라. 조치 요청 사항  (조치 내용 / 제출 자료 / 시기)
종합 의견          (1문단)
```

### 2-2. 보완요청본 — 요청자에게 "고쳐서 다시 내라"를 전달

```
과업심의 자료 보완 요청
{사업명} ({문서번호}, {시행일})
──────────────────────
1. 검토 개요        (대상 / 검토 자료 / 사업금액 / 적용 기준)
2. 보완 요청 사항 (A) — 상정 전   ← 과업범위·금액 판단에 직접 영향
3. 정정 요청 사항 (B) — 심의 시까지 ← 표기·정합성
4. 권고 사항
5. 확인 완료 — 추가 제출 불필요
회신 요청           (기한 근거 + "위원회 심의 결과가 아님" 명시)
```

**2-2의 편집 원칙**

- **수신자가 할 일만 남긴다.** 담당자(간사) 몫 — 제척·회피 처리, 대체위원 지명, 상정 일정 관리,
  심의결과서 기재, 과거 회차 대조 이력 — 은 **전부 뺀다.** 노트에는 남기고 전달본에는 싣지 않는다.
- **판정 등급을 그대로 쓰지 않는다.** "보완 후 확정" 같은 위원회 용어 대신
  **A(상정 전) / B(심의 시)** 로 시급성만 전달한다. 판정은 위원회 몫이다.
- **§5 "확인 완료 — 추가 제출 불필요"를 반드시 넣는다.** 무엇을 안 내도 되는지 알려주지 않으면
  적정 사업기간 산정서·직접구매 계획처럼 **대상도 아닌 서류를 만들어 온다.** 근거 조문과 함께 적는다.
- 각 지적은 `요청 —` 상자로 닫는다. 무엇을 어떤 형태로 낼지가 한 문장에 있어야 한다.
- 회신 기한은 **상대 문서의 일정**(사업계획서 계약 요청 기간 등)을 근거로 제시한다.

**제작**

1. HTML 작성 (A4, `@page { size: A4; margin: 20mm 18mm 18mm 18mm; }`)
2. `word-break: keep-all` 필수 — 없으면 한글이 단어 중간에서 끊긴다
3. 렌더
   ```bash
   "/c/Program Files/Google/Chrome/Application/chrome.exe" --headless --disable-gpu \
     --no-pdf-header-footer --print-to-pdf="<출력.pdf>" "file:///<절대경로>/review.html"
   ```
4. **검증** — PyMuPDF로 페이지를 PNG로 렌더해 Read로 레이아웃 확인. 표 열 폭 깨짐·강제 개행 점검.

## 3. 한글 문체

### 3-1. 산출물마다 문체가 다르다

| 산출물 | 독자 | 종결 | 비고 |
|--------|------|------|------|
| 볼트 노트 (심의의견·사전검토) | 본인·후임 담당자 | 평서형 `~다` 허용 | 판단 근거를 남기는 기록. 단정해도 된다 |
| 전달용 PDF (검토의견·보완요청) | 발주부서·위원회 | **개조식 명사형** `~함 / ~임 / ~없음 / ~바람` | 대외 문서. 아래 3-2~3-5 적용 |
| 채팅 응답 | 사용자 | 자유 | **그대로 옮기지 않는다** |

채팅에서 쓴 문장을 전달본에 복사하는 것이 가장 흔한 사고다.
`~한 셈이다` · `이미 깨져 있음` · `턱없이` 같은 표현이 그대로 실려 나간다.

### 3-2. 개조식 규칙 (전달본)

| 축 | 규칙 |
|----|------|
| 종결 | `~함 / ~임 / ~없음 / ~됨`, 요구는 `~ 바람`. "요구:" 대신 **`요청 — ~ 바람`** |
| 계층 | `□` → `○` → `-`. **표로 대체 가능하면 표를 쓴다** (대조표가 문장보다 강하다) |
| 번역투 | `~에 대한`·`~에 있어서` 제거. `~로 인해` → `~이므로`. 한 문장 안에 `대한`이 두 번 나오면 하나는 `~에 관한`으로 바꾸거나 지운다 |
| 피동 | 필요한 곳만. `산정되어졌다` 류 금지. 단 `반영되어 있지 않음`처럼 행위자를 지목하지 않으려는 피동은 유지 |
| 구어 | `~한 셈이다` → `~에 해당함` · `이미 깨져 있음` → `성립하지 않음` · `턱없이` → 수치로 |
| 문장 길이 | 지적 1건 = 근거 문단 + `요청` 상자. 근거는 3문장 이내 |

### 3-3. 표기 규범

| 대상 | 표기 |
|------|------|
| 법령·지침 | `「」`. 고시는 번호·시행일 병기 — 「…지침」(과학기술정보통신부고시 제2023-15호) |
| 조문 | `제10조제3항` (붙여 쓴다). 약식 `§10③`은 내부 노트에서만 |
| 인용문 | 별도 인용블록으로 빼고 **따옴표 중복 금지**. 원문 표기 그대로 |
| 날짜 | `2026. 8. 14.` — 마침표 3개, 각 마침표 뒤 한 칸 |
| 금액 | 천단위 콤마 + `원`. **원문 인용부는 원표기 유지**(`45~55백만원`, `50,000천원`) — 대조 가능성이 우선 |
| 수치 대조 | `A문서 21,900,000원 vs B문서 21,700,000원` 형태. 차액을 함께 적는다 |
| 한자 | 의미 혼동 소지가 있는 곳만 1회 병기 (`전재(轉載)`) |
| 영문 제품명 | 원문 표기 유지(`E&M Module`, `Node License`). HTML에서는 `&amp;` 이스케이프 확인 |

### 3-4. 어조

- **사람·부서를 주어로 삼지 않는다. 문서와 수치를 주어로.**
  `발주부서가 베꼈다` → `항목 구성·금액 범위·산출전제 문구가 모두 일치함`
  `담당자가 빠뜨렸다` → `산출내역서 어느 항목에도 계상되어 있지 않음`
- **단정 완화** — `틀렸음` → `~와 어긋남` / `~로 설명되지 않음` / `확인되지 않음`.
  다만 검토의견본의 종합 의견 1문단은 직설을 허용한다.
- **판단 불가는 판단 불가로 적는다.** 근거가 없는데 적정으로 넘기지 않는다.
- **선택지를 준다.** 하나의 정답을 강요하기보다 `아래 중 어느 방식인지 확정하고 근거를 제출 바람` 뒤에
  선택지를 나열하면 회신률이 높다.
- **익명화** — 대외 전달본의 특정 업체명 노출 여부는 사용자에게 확인한다.
  기본은 `RFI 회신 업체`. 다만 **조달 등록품목처럼 제품명이 곧 규격인 경우**는 표기한다.

### 3-5. 발행 전 자기검수

전달본을 PDF로 굽기 전에 아래를 훑는다.

1. 채팅 문체 잔재 — `~한 셈`, `~인 듯`, `엄청`, `말이 안 됨`
2. `~에 대한` 중복, `되어지`, `~로 인해`
3. 종결 혼용 — 한 문서에 `~다`와 `~함`이 섞였는지
4. 날짜·금액 표기 통일, 인용부의 원표기 보존
5. 담당자 몫 항목이 전달본에 남았는지 (2-2 원칙)
6. 렌더 후 **PNG로 페이지를 열어 눈으로 확인** — 표 열 폭 깨짐, 단어 중간 개행(`word-break: keep-all` 누락)

## 4. 상대 문서의 표기 검수

문체는 **내가 쓰는 규칙**이자 **상대 문서를 보는 눈**이다.
아래는 실제로 반복 검출된 항목이므로 검토 시 함께 확인해 보완요청본 §3(B)에 표로 싣는다.

| 유형 | 실측 사례 | 확인 방법 |
|------|----------|----------|
| 기관·제도명 오타 | `과엄심의위원회` (→ 과업심의위원회) | 문서 제목·근거 조항 인용부를 눈으로 |
| 금액의 모호어 | `50,000천원 정도` | `정도`·`내외`·`약` 검색 — 공문 금액란에는 부적절 |
| 부가세 표기 누락 | 심의요청서 사업금액란에 포함 여부 미표기 (산출내역서에는 "부가세 포함") | 금액이 나오는 모든 칸 대조 |
| 공문 마무리 | `1부.  끝` — 마침표 누락, 앞 공백 2칸 | 붙임 마지막 줄 |
| 항목 번호 누락 | 개요가 `추진배경 / 2. 사업개요 / 3. 기대효과` | 번호 열의 연속성 |
| 첨부 명칭 불일치 | 공문 붙임 `산출내역서` vs 심의요청서 첨부 `예산 산출내역서` | 공문 붙임 목록 ↔ 심의요청서 첨부 목록 ↔ 실제 파일명 3자 대조 |
| 단위 선언 위반 | "금액 단위: 천원"인데 일부 행이 원 단위 | `cost_check.py sum`으로 재검산 |

**제조사 작성본은 성격을 구분한다.** 규격서처럼 제조사가 만든 문서의 오기
(`커스커마이징`, `구매 기관은해당`)는 발주부서가 고칠 수 있는 문서가 아니다.
지적 본문에 섞지 말고 **참고 문단으로 분리**한 뒤,
"규격서는 검수 기준이 되는 문서이므로 제조사에 정정본을 요청하거나,
정정이 어려우면 해당 표기가 오기임을 계약 시 확인해 둘 것"으로 처리 방법을 붙인다.
