# 산출물 형식

## 0. 지적 문장 규격 — **모든 산출물 공통, 예외 없음**

지적 1건은 반드시 아래 4요소를 갖춘다. 하나라도 없으면 지적이 아니라 의견이다.

```
{근거} 에 따라 {당위} 하여야 하나, {대상 문서·위치} 에 {실제} 로 되어 있음.
요청 — {무엇을 어떤 형태로} 바람
```

| 요소 | 내용 | 없으면 |
|------|------|--------|
| 근거 | 법·시행령·고시 조문번호, 지침·가이드 문서명+장절, 또는 문서 간 대조 | 반박당한다 — "그건 관점 차이" |
| 당위 | 근거가 요구하는 상태. `~하여야 함` / `~여야 함` / `~할 수 없음` | 무엇이 문제인지 특정되지 않는다 |
| 실제 | 제출 문서의 현재 상태. 원문 인용 + 위치(문서명·쪽·표 이름) | 확인 불가 → 회신이 어긋난다 |
| 요청 | 수신자가 할 일 한 문장. `요청 — ~ 바람` | 무엇을 내야 할지 모른다 |

실례:

> **적정 사업기간 산정 주체 부적정** — 「소프트웨어사업 계약 및 관리감독에 관한 지침」
> (과학기술정보통신부고시 제2023-15호) 제10조제2항·제3항에 따라 사업금액 1억원을 초과하는 사업의
> 적정 사업기간은 **과업심의위원회가 산정하여야 하나**, 제출된 「적정 사업기간 산정표」(심의자료 5번,
> 2쪽)는 **발주부서 검토안으로 작성되어 있음**.
> **요청 —** 별지 제3호·제4호서식에 따른 위원회 산정 절차로 대체하고 그 결과를 제출 바람

### 0-1. 근거 등급 — L4는 지적이 아니다

| 등급 | 근거 | 처리 |
|------|------|------|
| L1 | 법률·시행령·고시 조문번호 (+ 고시번호·시행일) | 지적 (A) |
| L2 | 공식 가이드·기준의 문서명 + 장·절 (대가산정 가이드, 과업심의 가이드, 조달청 세부기준) | 지적 (A 또는 B) |
| L3 | 문서 간 정합성 — 같은 사업 문서가 서로 다르게 규정. 근거는 불일치 자체 | 지적 (B) |
| L4 | 관행·경험·일반론만 | 지적 금지 → 노트에만 기록. 전달본에는 싣지 않는다 (§2-2) |

L2·L3도 지적이지만 문장 안에 근거를 명시한다.
L3은 `A문서 {인용} vs B문서 {인용}` 대조 형태로 쓰고, 어느 쪽이 맞는지 단정하지 말고
어느 쪽으로 확정할지 회신을 요구한다.

### 0-2. 기계 검사

발행 전 반드시 돌린다. 실패하면 문장을 고친다.

```bash
python3 .claude/skills/gwaeop-simui/scripts/lint_findings.py "<노트 또는 전달본.md/.html>"
```

| 종료코드 | 뜻 |
|---|---|
| 0 | 검사한 지적이 모두 4요소 충족 |
| 1 | 미비 지적 있음 → 문장을 고친다 |
| 3 | 검사 대상을 찾지 못함 — 통과가 아니다. 표제·형식을 고치고 다시 돌린다 |

노트는 `지적사항`·`검토 필요 사항` 표제(`##` 이하)가, 전달본 A 항목은 `<div class="item">`이 있어야 인식된다.
통과가 곧 타당성 보증은 아니지만, 미비는 확실히 잡는다.

## 1. 볼트 노트 — `{...}_심의의견.md`

위치: `10_Areas/과업심의/{회차폴더}/{연월}_제{N}차과업심의_심의의견.md`
단일 사업 검토면 사업 폴더 안에 `심의의견_{확정요청번호}.md`.

선례: `10_Areas/과업심의/202607_제7차과업심의/202607_제7차과업심의_심의의견.md`

---
type: work

### 종합 판정

### 1-1. 판정(안) 등급 — 노트 전용

전달본에는 쓰지 않는다(판정은 위원회 몫). 상정 시 위원 참고용으로 노트에만 적는다.
회차마다 경계가 흔들리지 않도록 아래 기준을 그대로 쓴다.

| 등급 | 적용 |
|------|------|
| 원안 확정 | 지적사항 없음 또는 경미한 표기 오류뿐 |
| 조건부 원안 확정 | 금액·기간·과업범위는 타당, 공고 전 문구 보완으로 해소 가능 |
| 보완 후 확정 | 산출근거·견적·규격 등 자료 추가 제출이 있어야 판단 가능 |
| 재심의 | 사업금액 또는 적정기간의 근거 자체가 부재·왜곡 |

경계 판단은 A 항목(§2-3) 유무를 따른다 — A가 하나라도 있으면 최소 `보완 후 확정`이다.
절차 하자(축 0)로 심의 성립 자체가 문제면 등급 대신 보류로 적고 사용자에게 알린다.

작성 규칙

- 지적 1건 = 한 줄 제목(굵게) + 근거 + 요구 조치. 배경 설명으로 늘리지 않는다.
- 수치는 반드시 대조 형태로: `사업계획서 21,900,000원 vs 산출내역서 21,700,000원`
- "판단 불가"는 판단 불가로 적는다. 근거가 없는데 적정으로 넘기지 않는다.
- 재발 항목은 `references/recurring-defects.md`의 번호(A-4 등)를 병기한다.

## 2. 발주부서 전달용 PDF — **이 스킬의 최종 산출물**

전달본은 부산물이 아니라 목적물이다. 이 스킬이 서는 자리는
`과업심의_프로세스.md` Step 4(첨부 목록 검증) 이후 ~ Step 7(위원 발송) 이전,
즉 위원에게 나가기 전에 발주부서가 고칠 기회를 주는 간사 사전검토 단계다.
노트는 판단 근거를 남기는 기록이고, PDF는 그 자리에서 실제로 일을 시키는 문서다.

기본형은 2-2 보완요청본이다. 지적이 하나도 없거나 표기 오류뿐일 때만 2-1 검토의견본으로 낸다.
판정 등급(`보완 후 확정`·`재심의` 등)으로 고르지 않는다 — 판정은 위원회 몫이고,
사전검토 단계에서 등급을 확정하면 월권이다. 등급은 노트에만 남긴다.

발신 메타 4종을 반드시 싣는다 (템플릿 `assets/report.html`이 자리를 잡아 둔다).

| 항목 | 이유 |
|------|------|
| 요청 문서번호·시행일·확정요청번호 | 어느 건에 대한 회신인지 특정 |
| "과업심의위원회의 심의 결과가 아님" | 사전검토를 심의 결과로 오인해 위원회를 건너뛰는 것을 막는다 |
| 회신 기한 + 그 근거 | 아래 2-3 |
| 담당자·연락처 | 회신 경로. 없으면 회신이 오지 않는다 |

용도에 따라 골격이 갈린다 — 아래 2-1과 2-2를 혼동하지 않는다.

### 2-1. 검토의견본 — 심의 결과·판단을 전달

```
과업심의 검토의견
{사업명}
──────────────────────
1. 검토 개요      (검토 대상 / 사업 개요 / 검토 자료 / 대조 기준)
2. 검토 결론      (판정 + 처리의견 표)
가. 의결 전 해소 필요
나. 문서 정합성·법제도 표기   ← 표 형식이 읽기 쉬움
다. 과업 실현가능성
라. 조치 요청 사항  (조치 내용 / 제출 자료 / 시기)
종합 의견          (1문단)
```

### 2-2. 보완요청본 — 요청자에게 "고쳐서 다시 내라"를 전달

```
과업심의 자료 보완 요청
{사업명} ({문서번호}, {시행일})
──────────────────────
1. 검토 개요        (대상 / 검토 자료 / 사업금액 / 적용 기준)
2. 보완 요청 사항 (A) — 상정 전   ← 과업범위·금액 판단에 직접 영향
3. 정정 요청 사항 (B) — 심의 시까지 ← 표기·정합성
4. 확인 완료 — 추가 제출 불필요
회신 요청           (기한 근거 + "위원회 심의 결과가 아님" 명시)
```

권고 사항 절은 전달본에 없다. 예전 골격에는 §4 권고 사항이 있었으나, 실제 발행 때마다
사용자가 통째로 지웠다(4회차 연속). 이유는 명확하다 — 근거를 못 대는 항목을 "고쳐 달라"는
문서에 실으면 수신자는 무엇이 의무이고 무엇이 취향인지 구분할 수 없고, 문서 전체의 강제력이
같이 흐려진다. L4는 노트에만 남긴다.

2-2의 편집 원칙

- 수신자가 할 일만 남긴다. 담당자(간사) 몫 — 제척·회피 처리, 대체위원 지명, 상정 일정 관리,
  심의결과서 기재, 과거 회차 대조 이력 — 은 전부 뺀다. 노트에는 남기고 전달본에는 싣지 않는다.
- B 항목은 "위원이 오독할 수 있는" 불일치만 싣는다. 금액·기간·과업범위 해석을 바꾸지 않는
  단순 표기(오탈자·띄어쓰기·서식·목차 번호)는 노트에만 적고, 전달본에서는 마지막 B 항목 하나로
  묶어 "그 밖의 표기 오류 N건은 별첨 대조표 참조"로 닫는다. B가 4개를 넘으면 묶기 전에 다시
  본다 — 넘친다는 건 정합성 지적과 교정 지적을 섞고 있다는 신호다.
- 금액 구간을 먼저 확인하고 지적을 건다. 추정가격 2천만원 미만이면 소액수의계약이 가능하므로
  경쟁입찰·제안요청서·규격 공개를 전제한 지적은 성립하지 않는다(과업지시서로 작성하는 것이 정상).
  금액 전제가 틀린 지적은 회신 한 줄로 반박당하고, 나머지 지적의 신뢰도까지 깎는다.
- 분량을 줄여야 하면 순서는 L4 → 묶인 B → 개별 B다. A 항목과 회신 요청 절은 마지막까지 남긴다
  — 회신 기한이 빠지면 이 문서는 통보가 아니라 참고자료가 된다(§2-3). 다만 이 PDF를 별도 공문·메일에
  첨부해 보내고 그 본문이 기한을 이미 담고 있다면, 기한 문장이 두 곳에서 어긋날 수 있으니
  어느 쪽에 둘지 사용자에게 확인한다.
- 판정 등급을 그대로 쓰지 않는다. "보완 후 확정" 같은 위원회 용어 대신
  A(상정 전) / B(심의 시) 로 시급성만 전달한다. 판정은 위원회 몫이다.
- §5 "확인 완료 — 추가 제출 불필요"를 반드시 넣는다. 무엇을 안 내도 되는지 알려주지 않으면
  적정 사업기간 산정서·직접구매 계획처럼 대상도 아닌 서류를 만들어 온다. 근거 조문과 함께 적는다.
- 각 지적은 `요청 —` 상자로 닫는다. 무엇을 어떤 형태로 낼지가 한 문장에 있어야 한다.
- 회신 기한은 상대 문서의 일정(사업계획서 계약 요청 기간 등)을 근거로 제시한다.

### 2-3. 회신 기한 — 강제력은 기한의 근거에서 나온다

- 기한은 위원 발송일에서 역산한다. `A 항목 회신 기한 = 위원 자료 발송 예정일 − 2영업일`.
  근거를 문장에 적는다 — "제{N}차 과업심의 위원 자료 발송일이 {날짜}이며, 발송 전 반영이 필요함."
  상대 문서의 계약 요청 기간이 더 급하면 그쪽을 함께 근거로 든다.
  발송 예정일이 아직 없으면 날짜를 지어내지 말고 시점으로 닫는다
  ("과업내용 확정 심의요청서를 제출하기 전에 반영 바람") — 근거 문장은 그대로 붙인다.
- B 항목 기한은 심의 개최일 전까지. 표기·정합성은 위원 검토를 막지 않는다.
- **미보완·미회신 시의 불이익을 고지하는 문장은 싣지 않는다.** 아래 두 유형이 실제로 매번 삭제됐다
  (2026-09-08 사용자 상시 방침 확정, 그 전 회차에서도 동일하게 손으로 삭제).

  > 기한 내 회신이 없으면 제출된 자료를 원본 그대로 위원에게 송부하며, 본 검토 결과는 참고자료로 함께 제공됨.
  > 미보완 시 지적사항이 그대로 위원에게 전달됨.

  이 문서는 같은 기관 안에서 발주부서에 보내는 실무 협조 문서이지 통보문이 아니다.
  강제력은 각 지적의 근거 조문과 기한의 근거에서 나오지, 불이익 고지에서 나오지 않는다.
  미회신 시의 실제 처리(원본 그대로 상정 + 검토결과 참고 첨부)는 **간사 몫이므로 노트에만 적는다**
  → SKILL.md Step 6-5.
- 보완본이 오면 델타만 재검토한다 → SKILL.md Step 6.

## 3. 한글 문체

### 3-1. 산출물마다 문체가 다르다

| 산출물 | 독자 | 종결 | 비고 |
|--------|------|------|------|
| 볼트 노트 (심의의견·사전검토) | 본인·후임 담당자 | 평서형 `~다` 허용 | 판단 근거를 남기는 기록. 단정해도 된다 |
| 전달용 PDF (검토의견·보완요청) | 발주부서·위원회 | 개조식 명사형 `~함 / ~임 / ~없음 / ~바람` | 대외 문서. 아래 3-2~3-5 적용 |
| 채팅 응답 | 사용자 | 자유 | 그대로 옮기지 않는다 |

채팅에서 쓴 문장을 전달본에 복사하는 것이 가장 흔한 사고다.
`~한 셈이다` · `이미 깨져 있음` · `턱없이` 같은 표현이 그대로 실려 나간다.

### 3-2. 개조식 규칙 (전달본)

| 축 | 규칙 |
|----|------|
| 종결 | `~함 / ~임 / ~없음 / ~됨`, 요구는 `~ 바람`. "요구:" 대신 `요청 — ~ 바람` |
| 계층 | `□` → `○` → `-`. 표로 대체 가능하면 표를 쓴다 (대조표가 문장보다 강하다) |
| 번역투 | `~에 대한`·`~에 있어서` 제거. `~로 인해` → `~이므로`. 한 문장 안에 `대한`이 두 번 나오면 하나는 `~에 관한`으로 바꾸거나 지운다 |
| 피동 | 필요한 곳만. `산정되어졌다` 류 금지. 단 `반영되어 있지 않음`처럼 행위자를 지목하지 않으려는 피동은 유지 |
| 구어 | `~한 셈이다` → `~에 해당함` · `이미 깨져 있음` → `성립하지 않음` · `턱없이` → 수치로 |
| 문장 길이 | 지적 1건 = 근거 문단 + `요청` 상자. 근거는 3문장 이내 |

### 3-3. 표기 규범

| 대상 | 표기 |
|------|------|
| 법령·지침 | `「」`. 고시는 번호·시행일 병기 — 「…지침」(과학기술정보통신부고시 제2023-15호) |
| 조문 | `제10조제3항` (붙여 쓴다). 약식 `§10③`은 내부 노트에서만 |
| 인용문 | 별도 인용블록으로 빼고 따옴표 중복 금지. 원문 표기 그대로 |
| 날짜 | `2026. 8. 14.` — 마침표 3개, 각 마침표 뒤 한 칸 |
| 금액 | 천단위 콤마 + `원`. 원문 인용부는 원표기 유지(`45~55백만원`, `50,000천원`) — 대조 가능성이 우선 |
| 수치 대조 | `A문서 21,900,000원 vs B문서 21,700,000원` 형태. 차액을 함께 적는다 |
| 한자 | 의미 혼동 소지가 있는 곳만 1회 병기 (`전재(轉載)`) |
| 영문 제품명 | 원문 표기 유지(`E&M Module`, `Node License`). HTML에서는 `&amp;` 이스케이프 확인 |

### 3-4. 어조

- 사람·부서를 주어로 삼지 않는다. 문서와 수치를 주어로.
  `발주부서가 베꼈다` → `항목 구성·금액 범위·산출전제 문구가 모두 일치함`
  `담당자가 빠뜨렸다` → `산출내역서 어느 항목에도 계상되어 있지 않음`
- 단정 완화 — `틀렸음` → `~와 어긋남` / `~로 설명되지 않음` / `확인되지 않음`.
  다만 검토의견본의 종합 의견 1문단은 직설을 허용한다.
- 판단 불가는 판단 불가로 적는다. 근거가 없는데 적정으로 넘기지 않는다.
- 선택지를 준다. 하나의 정답을 강요하기보다 `아래 중 어느 방식인지 확정하고 근거를 제출 바람` 뒤에
  선택지를 나열하면 회신률이 높다.
- 익명화 — 대외 전달본의 특정 업체명 노출 여부는 사용자에게 확인한다.
  기본은 `RFI 회신 업체`. 다만 조달 등록품목처럼 제품명이 곧 규격인 경우는 표기한다.

### 3-5. 발행 전 자기검수

전달본을 PDF로 굽기 전에 아래를 훑는다.

1. 채팅 문체 잔재 — `~한 셈`, `~인 듯`, `엄청`, `말이 안 됨`
2. `~에 대한` 중복, `되어지`, `~로 인해`
3. 종결 혼용 — 한 문서에 `~다`와 `~함`이 섞였는지
4. 날짜·금액 표기 통일, 인용부의 원표기 보존
5. 담당자 몫 항목이 전달본에 남았는지 (2-2 원칙)
6. 렌더 후 PNG로 페이지를 열어 눈으로 확인 — 표 열 폭 깨짐, 단어 중간 개행(`word-break: keep-all` 누락)
7. `lint_findings.py` 통과 — 지적 4요소(근거·당위·실제·요청) 누락, L4 등급 잔존 (§0)
8. `{{` 자리표시자 잔존 — 템플릿에서 안 지운 칸
9. 발신 메타 4종 — 문서번호·"심의 결과 아님" 문구·회신 기한과 근거·담당자 연락처 (§2)

## 4. 상대 문서의 표기 검수

문체는 내가 쓰는 규칙이자 상대 문서를 보는 눈이다.
아래는 실제로 반복 검출된 항목이므로 검토 시 함께 확인해 보완요청본 §3(B)에 표로 싣는다.

| 유형 | 사례 | 확인 방법 |
|------|----------|----------|
| 기관·제도명 오타 | `과엄심의위원회` (→ 과업심의위원회) | 문서 제목·근거 조항 인용부를 눈으로 |
| 금액의 모호어 | `50,000천원 정도` | `정도`·`내외`·`약` 검색 — 공문 금액란에는 부적절 |
| 부가세 표기 누락 | 심의요청서 사업금액란에 포함 여부 미표기 (산출내역서에는 "부가세 포함") | 금액이 나오는 모든 칸 대조 |
| 공문 마무리 | `1부.  끝` — 마침표 누락, 앞 공백 2칸 | 붙임 마지막 줄 |
| 항목 번호 누락 | 개요가 `추진배경 / 2. 사업개요 / 3. 기대효과` | 번호 열의 연속성 |
| 첨부 명칭 불일치 | 공문 붙임 `산출내역서` vs 심의요청서 첨부 `예산 산출내역서` | 공문 붙임 목록 ↔ 심의요청서 첨부 목록 ↔ 실제 파일명 3자 대조 |
| 단위 선언 위반 | "금액 단위: 천원"인데 일부 행이 원 단위 | `cost_check.py sum`으로 재검산 |

제조사 작성본은 성격을 구분한다. 규격서처럼 제조사가 만든 문서의 오기
(`커스커마이징`, `구매 기관은해당`)는 발주부서가 고칠 수 있는 문서가 아니다.
지적 본문에 섞지 말고 참고 문단으로 분리한 뒤,
"규격서는 검수 기준이 되는 문서이므로 제조사에 정정본을 요청하거나,
정정이 어려우면 해당 표기가 오기임을 계약 시 확인해 둘 것"으로 처리 방법을 붙인다.
