# Mode 2: 표준화 (standardize) — 상세 절차

## Step 1: 파일 읽기

전체 내용을 Read로 읽는다. 긴 파일(2000줄+)은 분할 읽기한다.

## Step 2: 정보 추출 소스

| 항목 | 추출 소스 | 예시 |
|------|----------|------|
| 교육명 | H1 제목, 파일명 | "실전 SQL 튜닝(Oracle)" |
| 강사 | `강사:`, `teacher:`, 본문 언급 | "홍길동, OO대학교" |
| 일시 | `date created`, `날짜:`, 본문 | "2024-07-15" |
| 장소 | `장소:`, `위치:`, 본문 | "국가공무원인재개발원" |
| 교육 목표 | `목표:`, `목적:`, 첫 문단 요약 | "SQL 성능 최적화 실무 역량 강화" |

## Step 3: 구조 재배치 규칙

1. **Frontmatter 정비**
   - `type: training`, `status: open` 추가
   - `date created`, `date modified` 유지
   - `tag:`, `teacher:`, `title:`, `Date:`, `supabase_id:` 등 비표준 필드 제거
   - 제거한 frontmatter 값은 본문 해당 섹션으로 이동 (tag → ## 관련, teacher → 교육 정보)

2. **H1 제목 확인**
   - H1이 없으면 파일명 기반으로 생성
   - H1이 2개 이상이면 첫 번째만 H1, 나머지는 H2로 변환

3. **교육 정보 섹션 구성**
   - 추출한 메타데이터를 `## 교육 정보` 포맷으로 배치
   - 추출 불가 항목은 빈칸 처리

4. **본문 재배치**
   - 기존 H2 → `## 핵심 내용` 하위 H3으로
   - 기존 H3 → H4로
   - 기존 H1 (복수 시) → H3으로
   - 모든 내용, 마크업, 링크, 이미지 보존

5. **핵심 정리 생성**
   - 기존 요약/정리 섹션이 있으면 `## 핵심 정리`로 이동
   - 없으면 본문 기반으로 3개 takeaway 작성 (blockquote 형식)

6. **참고자료 수집**
   - 본문 내 법령 링크, 외부 URL, PDF 참조를 `## 참고자료`로 이동
   - 본문 맥락상 필요한 링크는 원위치에도 유지 (중복 허용)

7. **할 일 이동**
   - 기존 체크박스(`- [ ]`, `- [x]`) 항목을 `## 할 일`로 이동
   - Obsidian Tasks 플러그인 형식 유지 (`📅`, `➕`, `✅`)

## Step 4: 파일 쓰기

Write 도구로 전체 파일을 덮어쓴다. 반드시 전체 내용을 한 번에 쓴다.
