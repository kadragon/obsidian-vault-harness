# 과업심의 회차 운영 (간사)

회차 서류는 위원 서명이 걸린 공식 문서다. 값 하나가 틀려도 전 위원 재서명이 필요하므로, 판단 값은 사람이 정하고 옮기는 일은 스크립트가 한다.

## 1. 절차 원본은 필요한 Step만 읽는다

`10_Areas/과업심의/과업심의_프로세스.md`는 600줄에 가깝다. 통째로 읽지 말고 헤딩 줄 번호를 먼저 뽑아 해당 구간만 읽는다.

```bash
grep -n '^##' "10_Areas/과업심의/과업심의_프로세스.md"
```

그다음 Read의 `offset`/`limit`으로 아래 표의 Step 구간만 연다. 이 노트는 기존 업무 노트라 내용을 고치지 않는다. 절차가 바뀌었다고 판단되면 사용자에게 갱신 여부를 묻는다.

| 요청 | 읽을 구간 | 도구 |
| --- | --- | --- |
| 새 회차 셋팅, 파일명 통일, hwp 변환, 첨부 목록 검증 | `표준 폴더 구조`, Step 1~5 | `prod:hwpx` |
| 서약서·결과서·산정서 생성 | Step 6 (6-1~6-6은 스크립트 불가 시 수동 절차) | `round_setup.py generate` → `verify` |
| 외부위원 발송, 위원별 통합본 | Step 7, 7-2 | `round_setup.py bundle` / `merge_sign_bundle.py` |
| 위원 변경, 위원장 제척, 번호 없는 공문 | Step 8 | — |
| 생성 서류 검증, 발주부서 최종본 대조 | Step 9 | `round_setup.py verify` / `diff-final` |
| 승인 체크·검토의견·종합 서명란 이름·종합 산정서 | Step 10 | `prod:hwpx` `table.py` |
| 위원 회신 PDF 분리 | Step 11 | `pypdf` |
| 결과 보고(내부결재)·결과 안내 붙임, `결재상신/` | Step 12 | `pypdf` |

회차 고유 정보(사업 목록·위원 구성·심의일·진행 기록)는 회차 폴더의 `{연월}_제{N}차과업심의_사업목록.md`에 있다. 직전 회차 사업목록 노트도 선례로 함께 본다.

## 2. 스크립트

```bash
RS=.claude/skills/gwaeop-round-manage/scripts/round_setup.py
python3 $RS generate   "10_Areas/과업심의/{회차폴더}"            # Step 6 서류 + validate
python3 $RS verify     "10_Areas/과업심의/{회차폴더}"            # Step 9 대조 — 문제 0건이어야 완료
python3 $RS bundle     "10_Areas/과업심의/{회차폴더}" --pdf-dir {스크래치}   # Step 7-2 위원별 통합본
python3 $RS diff-final "{최종본 폴더}" "{번호}/심의자료"          # 발주부서 최종본 대조
```

- 설정 파일 `_round.json` 형식과 키별 판단 기준: `references/round-config.md`. 셋팅 첫 단계에서 이 파일을 회차 폴더 루트에 만든다.
- 이미 있는 파일은 덮어쓰지 않는다. 값을 고친 뒤 다시 만들 때만 `--force`.
- `bundle`의 일부 위원 재생성은 `--member {이름}`. 위원 1명을 수동으로 묶을 때는 `scripts/merge_sign_bundle.py --help`.
- `bundle`·`merge_sign_bundle.py`·`diff-final`은 Windows + 한글 + pywin32가 필요하다. 없으면 `python3 -m pip install pywin32`.
- 서식 원본은 `assets/forms/*.hwpx`(`{{토큰}}` 치환형, 출처는 `assets/forms/README.md`). 서식을 바꾸면 `tests/test_round_setup.py`를 돌린다.

## 3. 대필하지 않는 값

위원 판단 영역을 간사가 채우면 심의 자체가 무효 논란이 된다.

- 위원별 결과서의 승인 체크는 그 위원이 승인했다는 확인(구두·서면·전자서명 회신)이 있을 때만 채운다. 종합 결과서의 승인은 전원 승인이 확인된 뒤에만 채우고, 일부만 확인됐으면 사용자에게 묻는다.
- 적정 사업기간 산정서의 개월 수와 검토의견은 공란이 기본이다. 사용자가 값(예: "035는 3개월, 조건부 승인")을 주면 그 값만 넣는다.
- 위원 검토의견 본문을 사용자가 채워 달라고 하면 심의자료(과업지시서·사업계획서)를 실제로 읽고 사업별로 쓴다. 같은 회차에서 위원끼리 문장이 겹치지 않게 쓴다.
- 직위·소속은 직전 회차 서명본이나 위원 본인 답에서만 가져온다. 모르면 공란으로 두고 묻는다.

## 4. 파일을 다룰 때

- 한글 COM `Open()`은 원본 경로에 쓰지 않는다. 스크래치 사본에서 작업하고 결과만 회차 폴더에 둔다 — 종료 시 원본이 조용히 덮어써질 수 있다.
- `공통/`의 서식 원본(개인정보 동의서 등)은 수정하지 않는다. 회차 값은 통합본 쪽에서 바꾼다.
- hwpx 편집 뒤에는 `validate`와 한글 실행 `MainWindowTitle` 파일명 일치까지 확인해야 완료다. validate만 통과하고 한글에서 빈 문서로 열리는 경우가 있다.
- 원본 통합 PDF·발송 zip·`결재상신/` 삭제는 사용자 확인 뒤에 한다. 지우기 전에 사업목록 노트에 사실을 기록한다.
- 폴더 깊이 `회차/사업번호/분류/파일` 4단계는 이 폴더에 한해 허용된다(`10_Areas` 깊이 규칙 예외).

## 5. 마무리

- 회차 사업목록 노트의 할 일·처리 결과에 이번 작업을 남긴다(날짜 이모지 규칙은 `docs/conventions.md`).
- 결과를 보고할 때 생성·변경한 파일 수, `verify` 결과(문제 건수), 사용자가 확인해야 할 값(빈 직위, 승인 미확인 위원)을 따로 적는다.
- 위원 발송 메일·결과 안내 공문 본문이 필요하면 knue-gongmun-draft로 넘긴다.
