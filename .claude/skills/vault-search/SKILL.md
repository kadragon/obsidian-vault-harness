# Vault Search

Obsidian 볼트에서 관련 정보를 찾고 패턴을 분석하는 절차.

## 도구 우선순위

**QMD 우선, Grep/Glob 보조**:

| 검색 유형 | 1차 도구 | 2차 도구 |
|----------|---------|---------|
| 키워드/자연어 검색 | `qmd search "{검색어}" -n 10` (BM25) | Grep |
| 시맨틱/개념 검색 | `qmd vsearch "{자연어 질문}" -n 10` (벡터) | — |
| 복합 검색 (키워드+시맨틱) | `qmd query "{질문}" -n 10` (하이브리드+리랭킹) | — |
| 정확한 문자열 매칭 (프로시저명, 메뉴코드) | Grep | — |
| 태그 빈도 분석 | `obsidian tags counts sort=count` | Grep (count mode) |
| 노트 간 연결 | `obsidian backlinks file="{노트명}"` | Grep (위키링크 패턴) |
| 파일명 패턴 매칭 | Glob | — |

**QMD 명령어 레퍼런스**:

```bash
qmd search "{키워드}" -n 10          # BM25 키워드 (빠름, LLM 불필요)
qmd vsearch "{자연어 질문}" -n 10     # 벡터 시맨틱 (개념적 유사도)
qmd query "{질문}" -n 10             # 하이브리드 (BM25+벡터+LLM 리랭킹, 최고 품질)
qmd search "{키워드}" --json -n 10   # JSON 출력 (파싱 용이)
qmd get "{파일경로}"                  # 특정 문서 조회
```

**선택 기준**: 정확한 식별자(프로시저명, 메뉴코드, 태그) → Grep. 자연어/맥락 검색 → QMD.

## 검색 전략

### 전략 1: 프로시저/서비스 기반

프로시저명이나 서비스명이 주어지면:
1. `qmd search "{프로시저명}" -n 10` — 관련 노트 탐색
2. Grep으로 `14_Changes/incident/`, `14_Changes/improvement/`에서 정확 매칭 확인
3. 결과 부족 시 Grep으로 `90_Archive/`, `10_Areas/` 확장

### 전략 2: 메뉴 코드 기반

7자리 메뉴 코드(예: `3020927`)가 주어지면:
1. Grep으로 전체 볼트에서 해당 코드 검색 (정확 매칭에 적합)
2. 결과를 파일명의 날짜 패턴 기준으로 최근순 정렬

### 전략 3: 업무 태그 기반

`#업무/`, `#부서/` 태그가 주어지면:
1. Grep으로 전체 볼트에서 태그 문자열 검색 (정확 매칭)
2. 해당 업무 영역의 디렉토리에서 집중 검색

### 전략 4: 키워드/자연어 기반

자유 텍스트 키워드나 자연어 질문이 주어지면:
1. `qmd query "{질문}" -n 10` — 하이브리드 검색 (BM25+시맨틱+리랭킹)
2. 결과가 부족하면 `qmd vsearch "{질문}" -n 10`으로 시맨틱 범위 확장
3. 특정 문자열 확인이 필요하면 Grep 보조

### 전략 5: 기간 기반

특정 기간의 노트를 찾을 때:
1. 디렉토리 구조 활용: `{year}/{상반기|하반기}/`
2. Glob으로 파일명의 날짜 패턴 매칭: `*{YYYY-MM}*` 또는 `*{YYYY-MM-DD}*`
3. (최종 필터링) 결과가 많으면 frontmatter `date created` 확인으로 좁히기

### 전략 6: 에러 타입 기반

Exception 클래스명이 주어지면:
1. `qmd search "{Exception클래스명}" -n 10` — 관련 인시던트 탐색
2. Grep으로 `14_Changes/incident/`에서 정확 매칭 확인
3. `90_Archive/`로 확장
4. 동일 에러의 발생 빈도와 해결 패턴을 분석

### 전략 7: 시맨틱 유사도 기반

개념적으로 비슷한 노트를 찾을 때 (정확한 키워드를 모를 때):
1. `qmd vsearch "{상황 설명}" -n 10` — 벡터 유사도 검색
2. 결과 노트의 키워드를 추출하여 Grep으로 추가 탐색
3. 예시: "수강신청 기간에 동시접속 문제" → 정확한 프로시저명 모르지만 관련 노트 발견

## 결과 보고 형식

검색 결과는 다음 형식으로 보고한다 (기본 상한: **10건**):

```
## 검색 결과: "{검색어}"

**총 {N}건** 발견 ({검색 범위})

### 관련도 높음
1. **[노트 제목](경로)** — {핵심 내용 1줄} ({날짜})
2. ...

### 참고
1. **[노트 제목](경로)** — {관련 이유} ({날짜})
```

**관련도 판단 기준**:
- **높음**: 검색어가 제목 또는 `## 프로시저`/`## 메뉴` 섹션에 포함
- **참고**: 검색어가 본문에만 포함되거나 간접적으로 관련

결과가 10건 초과 시 최근순 상위 10건을 반환하고 추가 필터 조건을 제안한다.

## 패턴 분석

반복 발생하는 이슈를 요청받으면:
1. 동일 프로시저/메뉴에서 발생한 인시던트를 시간순으로 나열
2. 발생 빈도, 공통 원인, 해결 방안 유사성을 분석
3. 근본적 개선이 필요한지 판단하여 제안

## 검색 팁

- 한글과 영문 모두로 검색한다 (같은 개념이 혼용되는 경우가 많다)
- 프로시저명의 일부만으로도 검색한다 (예: `Hl0927` → `Hl0927Service`)
- XML 파일명 패턴: `{업무코드}_{유형}.xml` (예: `hl_3020927_u.xml`)
