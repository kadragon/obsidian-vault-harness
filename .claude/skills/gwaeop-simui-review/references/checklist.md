# 과업심의 검토 체크리스트 (축 0 + 5축)

각 항목은 원문 인용으로 확인 가능한 것만 지적한다.
`(개발)` 표시는 SW 개발사업 전용 — 물품구매·구독·임차 건에서는 건너뛴다.
조문 근거와 인용문은 `references/legal-basis.md`에 있다.

## 축 0. 심의 성립 요건 — **내용 검토 전에 먼저 본다**

절차 하자는 내용 지적보다 상위다. 여기서 걸리면 판정 자체를 보류하고 사용자에게 알린다.

| # | 확인 | 근거 |
|---|------|------|
| 0-1 | 간소화 심의 대상인가 — ① 총 사업금액(부가세 제외) 1억원 이하 ② 상용SW·표준화 보급 정보시스템 구매 ③ 기심의 사업의 변경 없는 추가. 지침 §7② "총사업규모"(부가세 포함, 직접구매 3억원 기준)와 다른 용어 — `legal-basis.md` §5 금액 기준 | 대학 운영지침 §5③ |
| 0-2 | 간소화 대상이면 위원 2인 이상 + 외부위원 과반수 이상 지명이 있었는가 | 대학 운영지침 §5③ |
| 0-3 | 정식 심의면 위원장 포함 5~10명 + 외부위원 과반수를 충족하는가 | 시행령 §45①②, 대학 운영지침 §3① |
| 0-4 | 재적 과반수 출석 + 출석 과반수 찬성 요건을 갖추는가 (서면·온라인 결의 포함) | 시행령 §46②, 대학 운영지침 §6②③ |
| 0-5 | 제척 사유가 있는 위원이 참여하지 않는가 — 특히 발주부서 결재권자가 당연직 위원장인 경우 | 대학 운영지침 §7①(2호 소속 기관·단체와 직접 이해관계), 시행령 §46③ |
| 0-6 | 위원장 제척 시 나머지 위원 중 재호선이 이루어졌는가. 2인 체제라면 심의 성립 불가 | 대학 운영지침 §6④ |
| 0-7 | 심의 대상이 위원회 소관인가 — 과업 내용(적정 사업기간 산정 포함) / 변경 / 계약금액·기간 조정 | 법 §50①, 대학 운영지침 §4 |
| 0-8 | 발주부서가 위원회에 출석하여 설명하였는가 (서면심의면 그 사유) | 대학 운영지침 §8 |
| 0-9 | 심의 안건이 빠짐없이 상정되었는가 — ① 과업내용(상세 요구사항)·비용산정 ② 적정 사업기간 산정 ③ 상용SW 직접구매 대상 제외 ④ SW영향평가 재평가 ⑤ 기관장이 심의가 필요하다고 인정한 안건 | 시행령 §47①, 지침 §25, 과업심의 가이드 Ⅱ-02(2) |
| 0-10 | 간소화 대상 판정이 대학 지침 기준인가 — 상위 지침 §25③은 6호(+감리사업·전자정부사업관리 위탁)이나 대학 운영지침 §5③은 3호뿐. 감리·PMO 위탁 사업은 대학 지침상 간소화 대상이 아니므로 정식 심의 | 지침 §25③, 대학 운영지침 §5③ |
| 0-11 | 심의 시기가 발주(입찰공고) 전인가 — 사업수행일정 부족 등 불가피한 경우에 한해 계약체결 전까지 허용. 이미 공고된 뒤의 심의요청은 사후 추인 | 지침 §25, 과업심의 가이드 Ⅱ-02 |
| 0-12 | 확정 대상 문서가 제안요청서(또는 과업지시서·입찰공고서)인가 — 사업계획서만 제출되고 RFP가 없으면 확정할 대상 문서 자체가 없음 | 과업심의 가이드 Ⅱ-02 「과업내용 확정 기준」 |

> **1억원 초과 사업을 2인 체제로 심의하는 것**이 실무에서 가장 흔한 하자다.
> 회차 위원 구성부터 확인하고 시작한다.
>
> 0-9는 **누락 탐지용**이다. 심의요청서가 과업내용만 올리고 직접구매 제외·영향평가 재평가를
> 안건에서 빠뜨린 채 "해당 없음"으로 처리했다면, 그 판단의 근거 문서를 요구한다.

| 1-7 `(개발)` | 역산 FP가 과업 규모와 정합하는가 (`cost_check.py fp`) | 현저한 과소산정 |
| 1-8 `(개발)` | 유지관리·운영비가 요율제/투입공수 어느 쪽으로도 설명되는가 | 양방향 모두 불성립 |

> 모두 흔들린다. 단독 지적이 아니라 연쇄 영향으로 쓴다.

## 축 2. 사업기간 `(개발)`

`scripts/cost_check.py period` 로 정량 대조한다.

| # | 확인 | 근거 / 흔한 결함 |
|---|------|-----------------|
| 2-0 | 별표 1 대상사업인가 — 컨설팅·운영유지관리·상용SW 도입(커스터마이징 포함) 은 제외 | 별표 1. 1)  ← "커스터마이징 전제"를 기간 단축 근거로 쓰면서 산정서를 낸 경우, 대상 여부부터 정리 |
| 2-1 | 적정 개발기간과 전체 계약기간이 분리 표기되었는가 | 전체 계약기간을 개발기간처럼 서술 |
| 2-2 | 산정표에 ①FP 기반 적정 개발기간 산정표가 실제로 있는가 | 법 §45①, 지침 §10①, 별표 1. 서술형 의견 5개 항목만 있으면 별표 1 미준수 |
| 2-3 | 본문이 언급한 근거자료가 실제로 첨부되었는가 | "12주 WBS로 산정" ← WBS 없음 |
| 2-4 | 유사사업 자료가 g2b.go.kr·spir.kr 조사자료인가 | 별표 1. 3)③ ← 업체가 제출한 자사 실적 목록은 해당하지 않음. 업종·과업 성격 유사성도 확인 |
| 2-5 | 사업금액 1억원 초과면 산정 주체가 과업심의위원회인가 | 지침 §10②③ ← 발주부서 "검토안"만 제출은 미흡 |
| 2-6 | 입찰공고문 또는 제안요청서에 "소프트웨어 개발사업의 적정 사업기간 산정 기준에 따른 사업"임을 명시했는가 | 지침 §10④ 전단 |
| 2-7 | 제안요청서에 첨부한 종합 산정서(별지 제4호)에서 위원명·서명이 제외(블라인드 처리한 스캔본)되었고, "원본 내용과 상이없음"이 명시되었는가 | 지침 §10④ 단서 ← 서명란이 살아 있으면 위반. "원본 내용과 상이없음"은 법령준수 점검의 준수 인정 요건 |
| 2-8 | 전문가 자문·시장 회신이 기간을 부정하지 않는가 | "현실성 낮다" 의견 미반영 |
| 2-9 | 적정 사업기간이 1년 초과면 장기계속계약을 체결하는가, 그리고 각 회계연도 예산 범위로 이행하는가 | 법 §45② ← 기준은 전체 계약기간이 아니라 적정 사업기간. 장기계속이면 차수 구분·차수별 계약금액·연도별 배분 확인 |
| 2-10 | 사업종료가 다음 회계연도에 속하면 이월 근거가 있는가 | 법 §45③ |
| 2-11 | 제안요청서에 종합 산정서(별지 제4호)가 **첨부 자체**되어 있는가, 제안요청서 사업기간이 산정기간 이상인가 | 지침 §10④ ← 2-7은 첨부본의 서명란, 이 항목은 첨부 누락. A-18 |

> 2-6·2-7·2-11이 적정 사업기간 첨부 요건의 **정본**이다 — 다른 파일은 이 행 번호만 가리킨다. 요건이 바뀌면 여기만 고친다.
> 홈페이지 개발은 FP가 아닌 M/M 단가로 규모를 산정해도 별표 1 적용 대상이다(2-0 판정 시 참고).

정량 대조 예시

```bash
# 제시 기간·인력으로 소화 가능한 규모 상한
python3 .claude/skills/gwaeop-simui-review/scripts/cost_check.py period --months 3 --headcount 3   # → 약 171 FP 이하
```
이 상한을 요구사항 건수·역산 FP와 나란히 놓으면 기간 산정의 성립 여부가 드러난다.

## 축 4. 법제도 준수 (SW진흥법 계열)

NIPA가 사전규격·입찰공고를 모니터링해 권고하는 18개 항목과 겹친다. **`nipa §N` 표시 행은 `nipa-compliance.md` §N의
명시 요소를 전부 대조**한다 — 조항이 "있다"가 아니라 요소가 "모두 있다"여야 준수다. 문구가 없으면 같은 절의 필수 명시 문구를 요청란에 제시한다.

## 축 5. 실현가능성·문서 정합성

| # | 확인 |
|---|------|
| 5-1 | 심의요청서 첨부목록 ↔ 폴더 실물 파일이 일치하는가 |
| 5-2 | 문서 내부 머리글·별첨 번호가 파일명과 일치하는가 |
| 5-3 | 법령·부처 명칭 표기가 현행인가 |
| 5-4 | 같은 사항을 두 곳에서 다르게 규정하지 않는가 (기간 기산점·이수기준·제품명·라이선스 채널) |
| 5-5 | 전문가 자문·TF 의견 중 미해결로 남은 항목을 "확정"으로 서술하지 않는가 |
| 5-6 | 시장 회신이 "곤란"으로 답한 기능이 필수 과업에 들어가 있는가 (비용 미반영) |
| 5-7 | 사업자 자기부담 과업이 있으면 회수 전제(수요·단가·기간)가 성립하는가 |
| 5-8 | 요구사항이 개별 단위로 적용단계·완료기준·검수방법을 갖는가 (그룹 단위 표만 있으면 미흡) |
| 5-9 | SLA에 목표값과 미달 시 감액 기준이 함께 있는가 |
| 5-10 | 기준 사용량 초과분이 "실비 별도 협의"로 열려 있는가 (계약 후 증액 통로) |
| 5-11 | 종료·인수인계(데이터 무상 이관·기술문서·SW임치·병행운영)가 규정되었는가 |
| 5-12 | 심의요청 결재권자와 심의위원장이 동일인인가 → 제척·회피 사안, 즉시 보고 |
| 5-13 | 요구사항이 「별지 제6호서식」(상세 요구사항 세부내용 작성표) 형태로 작성되었는가 — 기능·성능·시스템장비구성·인터페이스·데이터·테스트·보안·품질·제약사항 등 유형별 분류 (지침 §11①, 별표 2) |
| 5-14 | 문서 표기 검수 — 기관·제도명 오타, 금액의 모호어(`정도`·`내외`), 부가세 포함 여부 미표기, 공문 `끝.` 마침표, 항목 번호 누락, 첨부 명칭 3자 불일치, 단위 선언 위반 → 유형·확인방법은 `output-format.md` §4 |

> 5-14는 **제조사 작성본(규격서 등)과 발주부서 작성본을 구분**한다.
> 제조사 오기는 발주부서가 고칠 수 없으므로 지적 본문이 아니라 참고 문단으로 분리한다.
